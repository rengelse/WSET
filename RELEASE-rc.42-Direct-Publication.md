# WSET v1.4.4-rc.42 – Direct Website & Property Publication

## Implementert
- Eksisterende manuell to-ZIP-eksport beholdes. Ny «Overfør til server» etter generering, også via Publisering. Aktiv serverprofil og kontomappe/webrot bekreftes før en jobb startes. Fiks av eksisterende IPC-argumentfeil: valgt www/public/public_html sendes nå korrekt til generatoren.
- `server-publication.mjs` kartlegger genererte arkiver og boligeksport til eksplisitte serverstier; ZIP-filer valideres mot SHA-256 fra siste generering i aktiv prosjektøkt. Ingen serverinstallasjon eller server-side utpakking. Nettstedseksport avvises når prosjekt/relevante lokale XML-kilder eller assistentmodulvalg er endret.
- Offentlige filer går til valgt eksisterende webrot. `app/`, `config/`, `storage/` og `vendor/` ligger i kontomappen ved siden av webroten. Eksisterende `config/` og `storage/` beholdes, manglende filer/mapper kan opprettes. Backend og ressurser overføres før HTML. Ingen automatisk sletting av gamle offentlige filer.
- Eiendomsregisteret: «Overfør til server» for valgt Nybygg/Bruktboliger. Eksisterende eksportfunksjon brukes, inkludert godkjente egne annonser, bilder og metadata. Leverandør-XML beholdes som standard, eksplisitt valg for erstatning. Boligbilder med samme navn må være byte-identiske; konflikt stopper jobben. Bilder først, deretter XML og status. Egne boligfiler kontrolleres mot WSET-markør før eksisterende egen XML kan erstattes eller fjernes. Fjerningsvalg er av som standard; kan bare fjerne den kjente WSET-genererte XML-filen når uttrekket ber om dette. Andre XML-filer og bilder slettes ikke.
- Samme servertransport, tilkoblingssikkerhet, kø, avbrudd og historikk som rc.41. Midlertidige serverfiler ligger i privat kontomappe. Filstørrelseskontroll før og etter rename; jobb stopper etter første feil. Ingen endring av nettstedets layout, datamodell, oversettelsesmotor eller PHP-kilde i denne utgivelsen.

## Installasjon og bruk
1. Pakk ut full kildekode. `npm install` hvis rc.41-avhengighetene ikke allerede er installert; `npm run designer`.
2. Koble til en testprofil via Server / FTP. Kontroller at serverens kontomappe og webrot faktisk finnes og at WSET har tilgang til begge. Eksempel: kontomappe `/home/konto`, webrot `/home/konto/www`; på et chroot-webhotell kan kontomappen være `/` og webroten `/www`. Eksempelstier er ikke faktiske CBPM-opplysninger.
3. Generer nettstedet. Velg korrekt webrot i genereringsdialogen. Overfør siste eksport fra dialogen eller Publisering. Kontroller vert, konto og stier i bekreftelsen før start.
4. Første gang må nødvendige PHP-filer publiseres og serverinnstillinger, PHP-rettigheter og faktisk visning verifiseres. Ved senere boligoppdatering kan kategorien overføres direkte uten ny nettsidegenerering.
5. Sjekk kø/historikk. Behold eksisterende serverbackup. Ved feil: kontroller hvilke filer som ble fullført; rett feilen, start en ny publisering. Utdaterte offentlige filer må håndteres manuelt ut fra fjerningslisten. Overføringsjobben kan ikke rulles tilbake som helhet.

## Verifisering i testmiljø
- `npm run test:core`: 89 bestått, 0 feil, 3 hoppet over. Fem nye rc.42-tester for mapping, beskyttelse, arkivfingeravtrykk, symlenker, bilde/XML-rekkefølge, feil, tilbaketrekking og bekreftelse.
- `npm test`: 91 bestått, 4 feil (manglende eksterne Smart Assistant-ZIP/testprosjekt, ENOENT), 7 hoppet over.
- `tests/server-publication-rc42-project-check.mjs`: ekte CBPM-prosjekt, offline nettstedspakking med simulert Astro-runner (Smart Assistant av), 624 fullførte oppføringer via simulert filserver, alle offentlige filer verifisert byte for byte, serverdata bevart og kategorioverføring verifisert.
- Chromium med simulert IPC og migrert CBPM-prosjekt: direkte publisering, valg av webrot, kategori, sikre standardvalg, manglende tilkobling og utdatert eksport. rc.41-filbehandlerens UI-regresjon bestått.
- Ingen live SFTP/FTPS/FTP, native Electron-IPC, full Astro-bygg, eller faktisk PHP-webhotell er verifisert. Testmiljøet mangler nødvendige npm-avhengigheter for live protokolltest. SFTP-server må støtte sikker rename-erstatning; FTPS/FTP-server må støtte tilsvarende rename og overføring på tvers av konto/webrot innen samme filsystem. Rettigheter og eventuell chroot må verifiseres på webhotellet. SFTP-private filer opprettes med modus 0640 (serverens umask kan begrense videre); FTP(S) benytter serverens standardrettigheter. WSET stoler på serverens rapporterte filstørrelser; ende-til-ende sjekksum for alle filer, atomisk flersfilpublisering, automatisk speiling, differensiell overføring, backup og gjenoppretting kommer ikke i rc.42. Ingen server-side lås mot eksterne samtidige endringer. Automatisk retry av publiseringsjobber er ikke aktiv; start ny jobb via Publisering/Eiendommer.
